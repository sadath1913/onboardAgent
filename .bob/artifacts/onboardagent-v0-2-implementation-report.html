RAG Architecture

GitHub Repository
      ↓
clone_repository() — git clone, read-only flag fix (Windows)
      ↓
analyze_repository() — reads files, parser registry per language
      ↓
create_chunks() — semantic chunking by symbol/heading/window
      ↓
embed_texts() — sentence-transformers/all-MiniLM-L6-v2 (dim=384)
      ↓
PostgreSQL + pgvector — chunks table + embeddings table (vector(384))
      ↓
generate_llm_guide() — structured context → IBM LLM → Groq fallback
      ↓
Guide stored as Markdown in guides.content_md

User Question
      ↓
embed_query() → pgvector cosine similarity search (vector_search)
      ↓ + ILIKE keyword search over chunks (keyword_search)
      ↓ + ORM symbol name search (symbol_search)
      ↓ + relationship expansion (import/call graph)
      ↓
Ranked evidence items (top_k=8 default)
      ↓
IBM LLM → Groq fallback → evidence-only fallback
      ↓
Grounded answer with source citations [path:line-line]

Commands to Run the Upgraded System

# 1. Install dependencies
pip install sqlalchemy alembic psycopg2-binary pgvector sentence-transformers fpdf2 torch

# 2. Set required environment variables
set DATABASE_URL=postgresql://postgres:<password>@db.<project>.supabase.co:5432/postgres
set IBM_API_KEY=your-ibm-api-key          # optional but recommended
set GROQ_API_KEY=your-groq-api-key        # optional fallback

# 3. Apply database migrations (first-time setup)
alembic upgrade head

# 4. Start the application
python -m backend.main

# 5. Run tests (no DATABASE_URL needed)
python -m unittest tests.test_analyzer tests.test_github tests.test_service tests.test_server

# Optional: downgrade and re-upgrade to test migration
alembic downgrade -1
alembic upgrade head

Known Limitations

  • Deep AST parsing is currently implemented for Python, SQL, and Markdown. Java, Go, Rust, C/C++ etc. are indexed (files + content) but not deeply parsed — they use the generic parser and sliding-window chunking.
  • The IVFFlat index requires at least ~1000 vectors for efficient use; small repositories use sequential scan automatically.
  • Guide generation with LLM may hit context length limits for very large repositories; the guide_generator.py truncates context to fit.
  • Embedding model download (~90MB) happens on first use; subsequent runs use the cached model.
  • Integration tests against a live PostgreSQL instance require a valid DATABASE_URL; the test suite uses mocks for all DB-dependent tests.
  • PDF generation uses fpdf2 with latin-1 encoding — non-latin characters are replaced. For full Unicode PDF support, add a Unicode font to the FPDF instance.
